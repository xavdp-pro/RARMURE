## Interpretation limits

The prose in [Architecture](../ARCHITECTURE.md), [Cooperation](../AGENT-COOPERATION.md), and [Validation](../REQUIREMENTS-AND-VALIDATION.md) defines the intended system.

- Image 01 visually places agent sandboxes in a sequence. The intended architecture permits independent parallel sandboxes followed by combined validation.
- Image 03 places validated output cards near the provider protocol. A provider response does not directly become validated output: selection, counter-review, and combined validation remain required.
- Colors indicate illustrative contributions, not exclusive ownership of branches or fixed provider assignments.
- These images predate the explicit present boundary: only the master has direct agent read/write access to the present. Workers explore virtual candidates in RAM; a mounted candidate is a pinned test projection. The exploration graph represents sequences of moves separately from code containment.
- “Validated” cards depict possible future states, not tests that were run.
- Language extensions, file paths, and role descriptions are examples rather than product commitments.
- Latent communication remains separate deferred research.

## Prompt design record

The following are concise English summaries of the generation briefs, not verbatim copies of the full prompts.

1. **Shared tree:** a spacious editorial concept illustration with a translucent RAM graph, stable code references, overlapping agent intentions, durable database, semantic retrieval, isolated test views, a common specification, and deferred latent research.
2. **Fractal exploration:** evolve the shared-tree visual into recursive parallel branches with local feedback loops, retained failed experiments, sandbox evidence, and several fixed validated outputs while exploration continues.
3. **Counter-review:** add a reviewing role to every working cycle and to master decisions; show micro/macro evaluation and single-provider or multi-provider operation through a common explicit protocol.

The selected overview image is 03. No visual implies a working implementation or a demonstrated performance benefit.
